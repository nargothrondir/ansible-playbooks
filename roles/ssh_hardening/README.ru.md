# ssh_hardening

[English](README.md) | **Русский**

## Описание

SSH-усиление для хостов флота. Текущий объём (шаг 1 issue #30): открыть
**дополнительный порт sshd для автоматизации по ключу через NetBird-меш**.

Зачем второй порт: на пирах с включённым NB-SSH NetBird перехватывает
mesh-трафик на порт 22 (заворачивая его во встроенный JWT/SSO-сервер для
браузерного break-glass SSH из дашборда), поэтому классическая аутентификация
по ключу до sshd там не доходит. Ansible получает собственную дверь — порт,
который перехват не трогает. [Роль ufw](../ufw/README.ru.md) открывает его
только на mesh-интерфейсе; наружу он не выставляется.

Drop-in явно перечисляет и `Port 22`: первая директива `Port` отменяет
неявный дефолт, а несколько строк `Port` суммируются. Смёрженный конфиг
валидируется (`sshd -t`) до срабатывания handler'а перезагрузки.

Следующие шаги #30 (отключение паролей, root-логина, крипто-усиление) будут
расширять эту роль.

## Доверие к SSH CA флота

Необязательная вторая задача, выключенная, пока `ssh_hardening_ca_public_key`
пуста: положить публичный ключ удостоверяющего центра и велеть sshd принимать
подписанные им пользовательские сертификаты.

**Это добавляет способ входа и ни одного не убирает.** `authorized_keys` роль
не трогает, поэтому существующий ключ остаётся дверью, а сертификат, который не
прошёл проверку, просто не становится второй. Так задумано: неправильно
поставленный якорь доверия должен стоить неудавшегося опыта, а не запертой
двери. Убирается он без всякого плейбука — удалить
`/etc/ssh/sshd_config.d/20-ansible-ca.conf` и перезагрузить sshd.

Ключ пишется раньше drop-in'а, который на него ссылается: `TrustedUserCAKeys`,
указывающий на отсутствующий файл, заставляет sshd писать ошибку при каждой
попытке аутентификации. У обеих задач одно `when`, поэтому хост не остаётся с
половиной конструкции.

`AuthorizedPrincipalsFile` сознательно не настраивается. Без него sshd
принимает сертификат, среди принципалов которого есть имя целевого
пользователя, — ровно то правило, которое роль подписи в CA и так соблюдает при
выдаче.

После перезагрузки идут две проверки, и отвечают они на разные вопросы.
`sshd -t` говорит, что смёрженный конфиг разбирается; `sshd -T` говорит, что
именно он смёржил. Drop-in, который не был включён — нет строки `Include` в
`sshd_config` образа провайдера, — первую проходит, а во второй отсутствует.
Без второй проверки доверие к сертификатам выглядело бы установленным и не
делало бы ничего, а обнаружилось бы это входом, тихо откатившимся на ключ.

Зелёный прогон **не** доказывает, что вход по сертификату работает. Он
доказывает, что sshd отдаёт директиву. Вторая половина доказывается отдельно —
[playbooks/openbao-ssh-sign.yml](../../playbooks/openbao-ssh-sign.yml); их
соединение и есть вход, который выполняется руками по одному разу на хост.

Сам ключ лежит в OpenBao по пути `infra/ssh_ca` и читается на контроллере:
ноды до OpenBao не достают, его API живёт в docker-сети панели, а не в меше.
Передают его ноде двое —
[playbooks/provision-node.yml](../../playbooks/provision-node.yml) при сборке,
чтобы нода была полноценным членом флота с самого начала, и
[playbooks/ssh-ca-trust.yml](../../playbooks/ssh-ca-trust.yml) для той, что уже
существует.

## Переменные

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `ssh_hardening_mesh_port` | `automation_ssh_port` (2200) | Дополнительный порт sshd для автоматизации через меш; общий с ролью ufw через group_vars/all |
| `ssh_hardening_public_port` | `22` | Канонический публичный порт sshd в drop-in'е; переопределить на хостах, сознательно ушедших с 22 |
| `ssh_hardening_ca_public_key` | `""` | Публичный ключ CA флота (`infra/ssh_ca` в OpenBao). Пусто — учётные данные sshd не меняются; значение ставит доверие к сертификатам рядом с `authorized_keys` |
| `ssh_hardening_ca_path` | `/etc/ssh/trusted-user-ca.pub` | Куда этот ключ пишется. Публичен по построению, читаем всеми |

## Зависимости

Нет. В паре с ролью `ufw` (`ufw_mesh_tcp`) порт остаётся mesh-only.

## Пример

```yaml
- hosts: fleet
  become: true
  roles:
    - ssh_hardening
```

## Поддерживаемые ОС

Debian 12/13, Ubuntu 24.04.
