# Роль: hawser

[🇬🇧 English](README.md) · 🇷🇺 Русский

## Описание

Разворачивает агент [Hawser](https://github.com/Finsys/hawser) (для
[Dockhand](https://github.com/Finsys/dockhand)) на удалённом Docker-хосте в
**edge-режиме** — агент сам подключается к Dockhand по WebSocket наружу, поэтому
входящий порт/проброс не нужен (удобно для VPS/NAT и хостов за блокировками).

Каждый хост — отдельное окружение Dockhand со **своим токеном**.

## Откуда берётся compose-файл

**Роль его не рендерит.** Compose агента живёт в
[docker-stacks](https://github.com/nargothrondir/docker-stacks) в папке `hawser/`
— это его единственный источник; роль скачивает файл на закреплённом коммите и
разворачивает.

Два решения тут намеренные:

- **Скачивание на контроллере, не на ноде.** `raw.githubusercontent.com` местами
  блокируется там, где живёт часть флота, а провижининг не должен зависеть от
  доступности GitHub с ноды. Semaphore и так не начнёт прогон без GitHub, поэтому
  зависимость остаётся там, где она уже есть.
- **Пин по коммиту, не по ветке.** Хеш git — это адрес содержимого, значит пин
  одновременно и проверка целостности, а платформенный слой не едет за
  движущимся `main`. Бамп `hawser_compose_ref` — это и есть способ, которым
  правка compose доезжает до флота, и он оставляет её в истории **этого**
  репозитория, а не только чужого.

**Доставляет её мёрдж.** Шаблон `Sync Hawser` в Semaphore запускается сам, когда
в `ansible-playbooks` появляется коммит в `main` — опция шаблона *Auto-run task
if new git commit have been found*, репозиторий `ansible-playbooks`, интервал
проверки 10 минут. Renovate предлагает бамп пина, вы читаете диф compose и
мёржите, ближайшая проверка доставляет. Наружу при этом не открыто ничего:
Semaphore спрашивает GitHub, GitHub к нам не стучится.

Отслеживается именно этот репозиторий, а не `docker-stacks`, и это намеренно.
Что будет развёрнуто, решает `hawser_compose_ref`, который живёт здесь; коммит
там ничего не меняет, пока не сдвинут пин. Слежение за `docker-stacks` давало бы
прогоны, способные быть только холостыми, а затем — запомнив тот коммит —
молчало бы на бампе пина, ради которого всё и нужно.

Границы держит собственный `Limit` шаблона, сейчас `pl-1,controller`: автоматика
достаёт только до лабораторной ноды, флот по-прежнему обновляется руками.
`controller` в лимите нужен потому, что на него нацелен плей, читающий таблицу
токенов; без него прогон падает на страже в `playbooks/hawser.yml`.

Об это расписание легко споткнуться в трёх местах:

- Оно создаётся из формы шаблона и не получает имени, поэтому может не
  отображаться на странице Schedule. Убедиться, что оно есть, можно, открыв
  шаблон заново: галочка, репозиторий и интервал читаются из расписания, а не
  хранятся в шаблоне.
- Сохранение формы шаблона отправляет расписанию только `cron_format` и
  `repository_id`. Лимит, заданный на *расписании*, при этом молча пропадёт —
  поэтому лимит и живёт на шаблоне.
- Снятая галочка расписание не выключает. Она его удаляет.

**Никогда не разворачивайте эту папку как стек Dockhand From-Git.** Dockhand
велит агенту выполнить `compose up` над проектом, в который входит он сам; агент
останавливает собственный контейнер, а замена остаётся в состоянии `Created` —
процесс, который должен был её запустить, был внутри только что остановленного
контейнера. Измерено на лабораторной ноде 2026-08-13, нода была без управления до
прогона Ansible.

Значения пишутся в `.env` рядом с compose-файлом, откуда compose читает их сам.
`TOKEN` лежит только там — `0600` (только root), задачей с `no_log`, так что он не
читается кем угодно и не попадает в лог прогона.

## Ротация токена ноды

Два шаблона Semaphore, запускаются по порядку. Поля ввода у них
**противоположны** — это и есть самое лёгкое место для ошибки:

| Шаблон | CLI args | Limit |
|---|---|---|
| `Rotate Hawser token` | `-e node_name=<хост> -e dockhand_force_rotate=true` | **пусто** |
| `Sync Hawser` | пусто | `<хост>,controller` |

Плейбук ротации нацелен на контроллер и обращается только к API OpenBao и
Dockhand — на саму ноду он не заходит, поэтому лимит с её именем оставит плей
без хостов. Плейбук доставки на ноду заходит, поэтому лимит обязателен, а
`controller` нужен в нём потому, что отдельный плей читает там таблицу токенов
из OpenBao.

Аргументы `-e`, попавшие в поле Limit, приводят к безвредному отказу: Ansible
принимает каждое слово за имя хоста, не находит совпадений и останавливается до
запуска плеев.

Ротация удалась, если последняя строка — **`freshly minted and issued`**.
`already registered` означает, что `dockhand_force_rotate` не долетел и нового
токена нет; доставку в этом случае запускать нельзя.

Несколько нод делаются за один заход: ротация по очереди (плейбук принимает одну
DNS-метку за раз), затем один прогон доставки с
`Limit: <a>,<b>,<c>,controller`.

### Нода возвращается до пяти минут — это норма

Dockhand держит карантин по IP после неудачной авторизации агента,
`HAWSER_AUTH_FAIL_COOLDOWN_MS`, пять минут в v1.0.41. Проверка карантина стоит
**до** проверки токена.

Поэтому ротация всегда даёт паузу: выдача нового токена отзывает старый,
работающий ещё старый агент стучится отозванным и заносит собственный адрес в
карантин, а пришедший на смену агент отсиживает срок за предшественника.
Upstream сбрасывает карантин при успешной авторизации — то есть после проверки,
которая её и не допускает.

Измерено на fi 2026-08-17: контейнер пересоздан в 05:11:58, соединение принято в
05:15:02.

Карантин по IP, поэтому ноды не задерживают друг друга и пакет идёт не дольше
одной ноды.

**Как отличить норму от беды** по логу агента
(`docker logs hawser`, отфильтровав болтовню Docker API):

- `Connection failed: failed to receive welcome: server error:` с нарастающими
  паузами — карантин, надо ждать.
- `Invalid token` — на ноду доехал не тот токен, надо разбираться.

`Welcome received, environment ID: 0` ошибкой не является. В приветствии Dockhand
поля `environmentId` нет вовсе, хотя тип его объявляет, поэтому агент печатает
нулевое значение; привязка хранится на стороне сервера.

## Переменные

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `hawser_compose_ref` | _(закреплённый коммит)_ | Коммит docker-stacks, с которого берётся compose; бамп = принятие правки |
| `hawser_compose_repo` | `https://raw.githubusercontent.com/nargothrondir/docker-stacks` | Базовый raw-URL |
| `hawser_compose_path` | `hawser/docker-compose.yml` | Путь внутри репозитория |
| `hawser_compose_cache` | `/tmp/hawser-compose-<ref>.yml` | Кеш на контроллере; ref в имени, чтобы новый пин не подхватил старое содержимое |
| `hawser_dir` | `/opt/hawser` | Каталог compose-файла агента и его `.env` |
| `hawser_stacks_dir` | `/opt/hawser-stacks` | `STACKS_DIR` для стеков, управляемых Hawser |
| `hawser_request_timeout` | `120` | `REQUEST_TIMEOUT` агента (сек); дефолт 30 с обрывает долгие холодные деплои |
| `hawser_dockhand_url` | _(обязательна)_ | Edge-endpoint Dockhand (`wss://…/api/hawser/connect`), в `group_vars/all` |
| `hawser_token` | _(обязательна, vault)_ | Токен агента на хост (напр. из словаря `hawser_host_tokens` в `group_vars/managed/vault.yml`) |

## Зависимости

`community.docker` (для `docker_compose_v2`). На хосте должен быть установлен Docker.

## Пример

```yaml
- name: Deploy Hawser
  hosts: managed
  become: true
  tasks:
    - ansible.builtin.include_role:
        name: hawser
      when: hawser_token | default('') | length > 0
```

## Поддерживаемые ОС

Debian (bookworm, trixie), Ubuntu (jammy, noble).
